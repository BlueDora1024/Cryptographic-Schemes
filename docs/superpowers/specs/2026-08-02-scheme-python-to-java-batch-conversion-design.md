# Scheme Python 到 Java 批量转换设计

## 目标

以 `SchemeAAIBME/SchemeAAIBME.java` 为实现与风格基准，把仓库内其余所有 `Scheme*.py` 分别转换成同目录、同基本名的单文件 Java 源码。转换以静态语义核对为先，再通过编译和动态实验验证，确保 Java 实现保持对应 Python 算法、实验流程、控制台提示与输出数据的含义。

本次工作只修改本地仓库，不创建远程分支、不推送、不提交 Pull Request。现有的 `README.md` 和 `SchemeAAIBME/SchemeAAIBME.java` 修改必须保留，未跟踪的 `.DS_Store` 不纳入本次修改。

## 转换原则

### 单文件与独立性

每个 Java 文件独立包含运行所需的解析、数据保存、方案状态、算法阶段和 `main` 入口。可以在同一顶层类中使用私有静态嵌套类，但不得抽取跨方案共享的 Java 帮助类，也不得要求 Maven 或 Gradle。

Java 文件通过现有 `lib` 下的 JPBC、Apache POI 及其依赖运行。命令行采用 JDK 17 及以上版本的源文件模式，类路径由 `lib/fetchJavaDependencies.sh` 输出的依赖路径构成。

### 静态语义优先

转换每个方案前，逐项建立 Python 到 Java 的映射：

- 全局参数、主密钥、公钥、私钥、中间密钥与密文的数据结构；
- `Setup`、密钥生成、加密、转换、解密、验证等阶段的输入、输出和状态依赖；
- 群类型 `Zr`、`G1`、`G2`、`GT` 及每个配对运算的源群和目标群；
- 随机元素、哈希到群、指数运算、乘除、逆元和序列化行为；
- Python 中的条件分支、失败返回值、维度边界与循环范围；
- 时间复杂度、空间复杂度以及 Excel 列的计算方式。

Java 不机械照译 Python 语法。应使用 JPBC 的不可变元素或复制语义，避免可变 `Element` 运算意外修改已保存的密钥、参数或密文。涉及数组、列表和矩阵时，必须保留 Python 的索引范围和维度关系。

### 行为兼容

控制台输出中的提示词、大小写、标点和 `Yes`/`No` 结果与对应 Python 文件一致。命令行输出路径如果是相对路径，必须相对于当前 Java 源文件所在目录解析，而不是相对于进程工作目录解析。

Excel 中本质为整数的数值使用数值单元格写入，使其显示时不带无意义的小数部分；真实浮点值保持浮点语义。输出目录和工作簿创建失败时，应输出明确错误并以失败状态退出，不允许静默丢失实验结果。

### 曲线与配对参数

Python 实验矩阵中的曲线名称和顺序保持不变。对称方案优先使用与其 `SS512` 等配置一致的 JPBC 参数。

非对称方案只在存在准确且兼容的 JPBC 参数时运行相应曲线。若仓库和 JPBC 依赖中无法提供某个 Python 曲线名称的准确等价参数，则该配置必须被显式标记为不可用或无效，并继续处理其余配置；不得在原曲线名称下静默替换成另一条曲线。曲线不可用信息应同时进入控制台结果和实验输出，使用户能够区分“算法失败”和“运行环境缺少准确参数”。

## Java 代码风格

### 结构顺序

文件按以下顺序组织：标准库导入、外部库导入、顶层类。类内依次放置私有成员变量、受保护成员变量、公有成员变量、私有成员函数、受保护成员函数、公有成员函数，`main` 放在最后。构造函数视为同一符号，按参数数量从少到多排列；重载函数按符号整体排列。

所有导入在“标准库在前、外部库在后”的两个分组内分别按完整包名字母升序排列。

### 声明与权限

所有变量声明时必须赋初始值。局部常量使用 `final`，成员和函数使用满足设计要求的最小可见性。Java 不使用 C++ 风格的类型前 `const`。函数以最小安全单元检查输入、初始化状态、数组长度、空值和群类型，避免损坏状态继续传播。

### 排版与注释

缩进统一使用制表符。花括号采用 Allman 风格；跨行 lambda 和跨行初始化值按既定例外使用 K&R 风格。能在保持语义和警告检查通过的情况下省略控制语句花括号时可以省略。

注释全部使用语法正确的英文。行尾简单注释使用一个空格后接 `// `，内容通常小写开头；代码段说明置于上一行，使用 `/* ... */`，内容通常大写开头。Java 文件末尾不添加额外换行符。

## 实施顺序

第一批转换 8 个对称配对方案，从依赖和数据结构较简单的文件开始。每完成一个文件就立即进行静态检查、严格编译和最小动态实验，避免同类错误扩散到后续文件。

第二批转换 7 个非对称配对方案。先建立可用参数表，再转换算法；无法准确支持的曲线按上述不可用策略处理。`SchemeIBMECH` 的矩阵和群上高斯消元单独增加边界测试。

两批完成后更新 `.github/workflows/runJava.yml`，让 CI 覆盖所有 Java 源文件；更新 `README.md` 中 Java 文件链接、运行方式、依赖、输出路径规则和曲线兼容说明。不得删除或弱化现有 Python 文档。

## 错误处理

每个公开算法阶段均检查前置状态和参数类型。发现调用顺序错误、参数缺失、维度不一致、元素所属群错误或文件 I/O 错误时，返回与 Python 失败路径等价的结果，并提供可定位的英文错误信息。

动态实验中的单个安全参数或曲线失败不应导致其余配置被跳过；结果表必须记录该配置失败。只有源码无法编译、依赖不可读或输出文件整体无法创建等全局错误才终止该 Java 程序并返回非零状态。

## 验证策略

每个新增 Java 文件必须通过以下验证：

1. 使用项目声明的完整类路径和 JDK 17 以上版本进行源文件模式编译检查。
2. 使用 `-Xlint:all -Werror` 进行严格编译；第三方库自身的运行期版本提示不视为源码编译错误。
3. 运行缩小后的单配置实验，覆盖方案的成功路径和主要失败路径。
4. 核对关键代数等式、解密恢复结果、验证结果以及 Python 对应输出提示。
5. 检查相对输出路径从 Java 源文件目录解析，并确认 Excel 文件可打开、表头正确、整数单元格无小数尾部。
6. 对不可用的非对称曲线确认其被显式记录，且没有被其他曲线参数替代。
7. 完成全部文件后运行 CI 等价的全矩阵验证，并检查 `git diff --check`、导入排序、制表符缩进和 Java 文件末尾字节。

随机密码学实验不要求 Python 与 Java 生成相同随机元素或相同运行耗时；验收依据是算法关系、成功/失败语义、实验矩阵、提示文本和输出结构一致。

## 完成标准

- 15 个目标 Java 单文件全部存在，并能在受支持配置下编译和运行。
- 每个文件保留对应 Python 的算法阶段、实验矩阵和输出语义。
- 不支持的精确曲线被明确标记，不存在静默替换。
- CI 工作流与 README 覆盖全部 Java 实现。
- 本次新增或修改的 Java 文件符合既定排序、权限、初始化、缩进、花括号、英文注释、导入顺序和文件结尾规范。
- 原有未提交修改得到保留，`.DS_Store` 未被纳入成果。
